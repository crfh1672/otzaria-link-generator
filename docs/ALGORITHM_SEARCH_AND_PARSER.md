## 1. ארכיטקטורה כללית ומבנה ה-Pipeline

מנוע הזיהוי בנוי כצינור עיבוד נתונים (Data Pipeline) רב-שלבי המקבל טקסט תורני גולמי ומחלץ מתוכו קישורים מבוססי מראות מקומות (Citations) אל ספריית אוצריא.

```
[טקסט תורני גולמי]
        │
        ▼
[1. נרמול ואינטגרציית ראשי תיבות] ──> (cleanText + expandAbbreviations)
        │
        ▼
[2. חלוקה לאסימונים וסריקת חלונות] ──> (Tokenization & Sliding Window Scanner)
        │
        ▼
[3. סינון תבניות וזיהוי מילות מפתח] ──> (Regex Regex & Context Identifiers)
        │
        ▼
[4. חישוב גימטריה ומשקלי מילים] ──> (gematria & wordWeights System)
        │
        ▼
[5. חיפוש גמיש והתאמת ספרים במאגר] ──> (Fuzzy Match & Otzaria Library Index)
        │
        ▼
[6. מנוע חישוב ציון ודירוג מועמדים] ──> (Score Engine & Candidate Ranking)
        │
        ▼
[רשימת קישורים מוצבעת ומדורגת (CitationMatches)]
```

## 2. מנוע המרת גימטריה ומספרים

המערכת כוללת מנגנון דו-כיווני להמרת מחרוזות אותיות עבריות לערכים נומריים ולהיפך.

### 2.1 המרת אותיות למספר (`gematria`)
פונקציית `gematria(str: string): number` ממירה מחרוזת עברית לערכה הנומרי בגימטריה רגילה (Standard Gematria):
* **א'-ט'**: $1$ עד $9$
* **י'-צ'**: $10$ עד $90$
* **ק'-ת'**: $100$ עד $400$
* **אותיות סופיות**: ממופות לערכן הרגיל (ך = 20, ם = 40, ן = 50, ף = 80, ץ = 90).

#### לוגיקת הטיפול באותיות שימוש וראשי תיבות:
1. הפונקציה מנקה תוים שאינם אותיות עבריות (כגון מירכאות, גרשיים, מקפים).
2. במידה והמחרוזת כוללת אותיות קידומת (כגון ב', כ', ל', מ', ש', ו') שלפני ציון מספר (כמו "ובדף", "בלמד"), האלגוריתם מזהה ומבודד את סיומת האותיות המייצגת את המספר.
3. מתבצע סכום של ערכי כל האותיות במחרוזת.

### 2.2 המרת מספרים לאותיות (`numberToGematria`)
פונקציית `numberToGematria(num: number): string` ממירה ערך נומרי חיובי חזרה לייצוג עברי תקני לפי המסורת:
1. **טיפול בשמות ה' (מניעת חילול השם ופורמט מקובל)**:
   * המספר $15$ מומק כ-`ט"ו` (ולא `יה`).
   * המספר $16$ מומק כ-`ט"ז` (ולא `יו`).
2. **פירוק למאות, עשרות ויחידות**:
   * עבור $400$ ומעלה: שימוש ב-`ת'` וחזרות במידת הצורך (תת, תתר, וכו').
   * מפות מאות: $100=$ ק, $200=$ ר, $300=$ ש, $400=$ ת.
   * מפות עשרות: $10=$ י, $20=$ כ, $30=$ ל, $40=$ מ, $50=$ נ, $60=$ ס, $70=$ ע, $80=$ פ, $90=$ צ.
   * מפות יחידות: $1=$ א, $2=$ ב, $3=$ ג, $4=$ ד, $5=$ ה, $6=$ ו, $7=$ ז, $8=$ ח, $9=$ ט.
3. **עיצוב מירכאות וגרשיים (Formatting)**:
   * עבור אות יחידה (כגון $3$): מתווסף גרש בסופה (`ג'`).
   * עבור שתי אותיות ומעלה (כגון $184$): מתווספות מירכאות לפני האות האחרונה (`קפ"ד`).

## 3. מנגנון ניקוי ונרמול טקסט

מנגנון `cleanText(text: string): string` מבצע סדרה של פעולות נרמול (Text Normalization) המבטיחות כי השוואות המחרוזות יתבצעו בצורה נקייה וללא תלות בשינויי עיצוב או תווי ניקוד.

### שלבי הניקוי:
1. **הסרת ניקוד וטעמי מקרא**:
   * שימוש ברקע רגולרי להסרת תווי Unicode בטווח `\u0591` עד `\u05C7` (כולל דגש, שווא, קמץ, פתח, חולם, שורוק, טעמי מקרא כגון אתנחתא, סגולתא וכו').
2. **נרמול מירכאות וגרשיים**:
   * המרת מגוון תווי גרשיים סופרים/טפשייים (`, ״, ", ‟, ”, „) לגרשיים תקניים (`"`).
   * המרת מגוון תווי גרש (', ׳, ’, ‘) לגרש תקני (`'`).
3. **הסרת תוים מיוחדים ומקפים**:
   * המרת מקפים רופים, מקפי-סופרים (־, -, –) לרווח בודד.
   * הסרת סוגריים עגולים `()`, מרובעים `[]`, מסולסלים `{}` וסימני פיסוק (נקודה, פסיק, נקודתיים, סימן שאלה, סימן קריאה).
4. **דחיסת רווחים**:
   * צמצום רצפי רווחים מרובים לרווח בודד אחד והסרת רווחים בקצוות (`trim`).

## 4. מילון ומנגנון הרחבת ראשי תיבות

בספרות התורנית נעשה שימוש נרחב ביותר בראשי תיבות וקיצורים. המערכת כוללת מילון מובנה עשיר (`abbreviations.ts`) המכיל מעל 400 ערכים תורניים, לצד מנוע התאמה והרחבה אינטליגנטי.

### 4.1 מבנה מילון ראשי התיבות (`ABBREVIATIONS_DICTIONARY`)
כל ערך במילון כולל:
* `short`: המחרוזת המקוצרת (לדוגמה: `"רש"י"`, `"או"ח"`, `"שו"ע"`, `"תוס'"`).
* `full`: ההרחבה המלאה (לדוגמה: `"רבי שלמה יצחקי"`, `"אורח חיים"`, `"שולחן ערוך"`, `"תוספות"`).
* `category`: קטגוריה סמנטית (`"ספרים"`, `"פרשנים"`, `"מונחים"`, `"מסכתות"`).
* `weight`: משקל חשיבות תורני.

#### דוגמאות מתוך המילון:
* **ספרים וחלקי ספרים**:
  * `או"ח` $\rightarrow$ אורח חיים
  * `יו"ד` $\rightarrow$ יורה דעה
  * `אהע"ז` / `אה"ע` $\rightarrow$ אבן העזר
  * `חו"מ` $\rightarrow$ חושן משפט
  * `שו"ע` $\rightarrow$ שולחן ערוך
  * `רמב"ם` $\rightarrow$ רבי משה בן מיימון / משנה תורה
  * `ע"ז` $\rightarrow$ עבודה זרה
  * `ר"ה` $\rightarrow$ ראש השנה
* **מפרשים**:
  * `רש"י` $\rightarrow$ רבי שלמה יצחקי
  * `תוס'` / `תוספ'` $\rightarrow$ תוספות
  * `רמב"ן` $\rightarrow$ רבי משה בן נחמן
  * `רשב"א` $\rightarrow$ רבי שלמה בן אדרת
  * `ריטב"א` $\rightarrow$ רבי יום טוב בן אברהם אלאשבילי
  * `מג"א` $\rightarrow$ מגן אברהם
  * `ב"ח` $\rightarrow$ בית חדש
* **מילות מכוונות מיקום**:
  * `פ"` / `פ"א` $\rightarrow$ פרק / פרק א'
  * `סעי'` / `סע'` $\rightarrow$ סעיף
  * `סי'` $\rightarrow$ סימן
  * `ד"ה` $\rightarrow$ דיבור המתחיל
  * `ע"א` $\rightarrow$ עמוד א
  * `ע"ב` $\rightarrow$ עמוד ב

### 4.2 אלגוריתם ההרחבה (`expandAbbreviations`)
1. **סריקה מבוססת Regex לאסימונים**:
   * הזיהוי מתבצע תוך התחשבות במירכאות פנימיות (`"`) ובגרש בסוף מילה (`'`).
2. **טיפול באותיות השימוש**:
   * אם מופיעה מילה כגון `"ובשו"ע"`, האלגוריתם מפריד את אות השימוש `"ו"` ומורחב ל-`"ובשולחן ערוך"`.
3. **שמירת מיקומים ומניעת שיבוש אינדקסים**:
   * המנגנון שומר מיפוי מיוחד בין אינדקס התו בטקסט המורחב לבין אינדקס התו המקורי בטקסט המשתמש, על מנת להבטיח שהדגשת הקישור במסמך תהיה מבוססת בדיוק על המילים שהקליד המשתמש.

## 5. מערכת משקלי המילים ופילטור מילות עצירה

אחד האתגרים המרכזיים בזיהוי מראות מקומות תורניים הוא מניעת התאמות שווא (False Positives) הנובעות ממילים שכיחות במיוחד כגון "אמר", "דרש", "אלא", "שנאמר". המערכת משתמשת במודל השקלה ייעודי (`wordWeights.ts`).

### 5.1 מילות עצירה וקביעת משקלים נמוכים (`COMMON_TALMUDIC_WORDS`)
מילים המופיעות בתדירות גבוהה בטקסט תורני מקבלות משקל שלילי או נמוך במיוחד (קרוב ל-0), כך שלא ישפיעו על ציון ההתאמה:
* מילות אמירה ודרשה: `אמר`, `דאמר`, `ואמר`, `תנו רבנן`, `תנא`, `תנן`, `איתמר`, `דרש`, `אמר רב`, `אמר רבי`.
* מילות קישור ודיון: `אלא`, `ואלא`, `שנאמר`, `דכתיב`, `וכתיב`, `אימא`, `הכי`, `נמי`, `הכא`, `התם`, `מאי`, `כמאן`.
* מילות סוף פסוק/ציטוט: `וגו'`, `וכו'`, `שלם`, `עיין שם`, `ע"ש`, `וקל להבין`.

### 5.2 משקלים מוגברים למילות מפתח ומכווני מיקום
מילים המעידות על ציטוט או מיקום מוגדר מקבלות משקל חיובי גבוה:

| קטגוריית מילה | דוגמאות מילים | משקל יחסי | תפקיד באלגוריתם |
| :--- | :--- | :--- | :--- |
| **מכווני מיקום מרכזיים** | `דף`, `עמוד`, `פרק`, `סימן`, `סעיף`, `הלכה`, `פסוק` | **1.8 – 2.5** | זיהוי מובהק של מבנה ציטוט תורני |
| **שמות מסכתות** | `ברכות`, `שבת`, `עירובין`, `פסחים`, `סנהדרין` | **2.2 – 3.0** | זיהוי מובהק של מסכת בש"ס |
| **שמות חלקי שו"ע/רמב"ם** | `אורח חיים`, `יורה דעה`, `יסודי התורה`, `שבת` | **2.5 – 3.2** | זיהוי מובהק של חטיבת הלכה |
| **מפרשים מרכזיים** | `רש"י`, `תוספות`, `רמב"ם`, `רמב"ן`, `רא"ש` | **2.0 – 2.8** | זיהוי מפרש ספציפי |
| **מילת דיבור המתחיל** | `ד"ה`, `דיבור המתחיל` | **1.9** | זיהוי תחילת ציטוט מפרש |

## 6. אלגוריתמי חיפוש גמיש ודמיון מחרוזות

קליטת טקסט עשויה להכיל שגיאות הקלדה, כתיב חסר/מלא (כגון "ברכות" לעומת "ברכת", "שולחן" לעומת "שלחן"), או שוני קל באותיות היחס. לשם כך משולבות פונקציות דמיון גמיש (`fuzzyUtils.ts`).

### 6.1 אלגוריתם מרחק לוינשטיין (Levenshtein Distance)
האלגוריתם מחשב את מספר הפעולות המינימלי (הכנסה, מחיקה או החלפה של תו) הנדרש להפיכת מחרוזת $A$ למחרוזת $B$:

$$\text{Lev}(i, j) = \begin{cases} 
\max(i, j) & \text{if } \min(i, j) = 0, \\
\min \begin{cases} 
\text{Lev}(i-1, j) + 1 \\
\text{Lev}(i, j-1) + 1 \\
\text{Lev}(i-1, j-1) + 1_{(A_i \neq B_j)}
\end{cases} & \text{otherwise.}
\end{cases}$$

### 6.2 יחס דמיון יחסי (Similarity Ratio)
על בסיס מרחק לוינשטיין, מחושב יחס הדמיון בטווח $[0.0, 1.0]$:

$$\text{Similarity}(A, B) = 1.0 - \frac{\text{LevenshteinDistance}(A, B)}{\max(\text{length}(A), \text{length}(B))}$$

* אם `Similarity >= 0.85` $\rightarrow$ ההתאמה נחשבת לגבוהה (High Match).
* אם `0.65 <= Similarity < 0.85` $\rightarrow$ ההתאמה נחשבת בינונית/גמישה (Fuzzy Match).
* אם `Similarity < 0.65` $\rightarrow$ ההתאמה נדחית.

### 6.3 מנגנון חפיפת אסימונים ותנודות כתיב חסר/מלא
1. **הסרת אי-דיוקים מורפולוגיים**: הסרת סיומות עבריות נפוצות (`ים`, `ות`, `יה`, `ין`) בעת השוואת שמות מסכתות ופרקים.
2. **בדיקת חפיפת תוים (Character Token Overlap)**: ספירת התוים המשותפים ביחס לאורך המילה לזיהוי חילופי אותיות אהו"י.

## 7. סריקת חלונות, חלוקת אסימונים וזיהוי תבניות ציטוט

אלגוריתם החיפוש הראשי (`parseCitations` / `parseTextForLinks`) עושה שימוש בטכניקת **חלון נייד (Sliding Window)** מעל אסימוני הטקסט.

### 7.1 תהליך החלוקה והסריקה:
1. הטקסט מפורק למערך אסימונים (Tokens) לפי רווחים, תוך שמירת אינדקס ההתחלה והסיום של כל אסימון בטקסט המקורי.
2. המערכת מריצה חלונות בגדלים משתנים של **1 עד 10 מילים**:
   * חלון קטן (1–2 מילים): זיהוי שם ספר בודד או מסכת (למשל: "ברכות ב.").
   * חלון בינוני (3–5 מילים): זיהוי ציטוט סטנדרטי (למשל: "רש"י מסכת ברכות דף ב ע"א").
   * חלון מורכב (6–10 מילים): זיהוי ציטוט מורחב כולל דיבור המתחיל (למשל: "שולחן ערוך אורח חיים סימן קנח סעיף א ובמגן אברהם ס"ק ג").

### 7.2 תבניות רגולריות מרכזיות (Regex Patterns)
האלגוריתם משתמש בביטויים רגולריים מתקדמים לזיהוי מבנים תורניים מוכרים:

1. **תבנית תלמוד בבלי (מסכת + דף + עמוד)**:
   ```regex
   /(?:מסכת|במסכת)?\s*([א-ת\s]+)\s+(?:דף|ד")?\s*([א-ת]{1,3})\s*(?:עמוד|ע")?\s*([אב12\.\:]?)/
   ```
   * דוגמאות נתמכות: `ברכות דף ב ע"א`, `ברכות ב.`, `ברכות ב:`, `במסכת שבת דף קנו עמוד ב`.

2. **תבנית שולחן ערוך / טור (חלק + סימן + סעיף)**:
   ```regex
   /(?:שו"ע|שולחן ערוך|טור)?\s*(אורח חיים|או"ח|יורה דעה|יו"ד|אבן העזר|אהע"ז|חושן משפט|חו"מ)\s+(?:סימן|סי')?\s*([א-ת]{1,3})\s+(?:סעיף|סע'|סקי|ס"ק)?\s*([א-ת]{1,3})?/
   ```
   * דוגמאות נתמכות: `שו"ע או"ח סימן קנח סעיף א`, `טור יו"ד סי' שפ`, `אהע"ז סימן מ סעיף ג`.

3. **תבנית רמב"ם (הלכות + פרק + הלכה)**:
   ```regex
   /(?:רמב"ם|משנה תורה)?\s*(?:הלכות|הל'|הלכותיו)\s+([א-ת\s]+)\s+(?:פרק|פ")?\s*([א-ת]{1,3})\s+(?:הלכה|הל'|אות)?\s*([א-ת]{1,3})?/
   ```
   * דוגמאות נתמכות: `רמב"ם הלכות שבת פרק א הלכה ב`, `הלכות תפילה פ"ה הלכה ה`.

4. **תבנית מקרא (ספר + פרק + פסוק)**:
   ```regex
   /(?:ספר)?\s*([א-ת\s]+)\s+(?:פרק|פ")?\s*([א-ת]{1,3})\s+(?:פסוק|פס'|אות)?\s*([א-ת]{1,3})?/
   ```
   * דוגמאות נתמכות: `בראשית פרק א פסוק א`, `ישעיהו מ' ג'`.

## 8. נוסחת חישוב הניקוד המלאה והדירוג

כל מועמד להתאמה (Candidate Match) שנמצא בחלון הסריקה עובר הערכה משוקללת ומקבל ציון סופי בטווח $0$ עד $100$ נקודות.

### 8.1 מרכיבי הציון (Score Components Breakdown)

$$\text{Final Score} = S_{\text{base}} + S_{\text{gematria}} + S_{\text{book}} + S_{\text{proximity}} + S_{\text{context}} - P_{\text{common\_words}} - P_{\text{length\_diff}}$$

#### 1. ציון בסיס טקסטואלי ($S_{\text{base}}$): עד 40 נקודות
* התאמה מדויקת (Exact String Match) מילה במילה: **40 נקודות**.
* התאמה גמישה (Fuzzy Match): $40 \times \text{SimilarityRatio}$.

#### 2. ציון התאמת גימטריה ומיקום ($S_{\text{gematria}}$): עד 25 נקודות
* התאמה מדויקת של ערך הגימטריה של הפרק / הדף / הסימן / הסעיף המופיעים בציטוט מול האינדקס בספר:
  * התאמת דף ועמוד מדויקת (למשל "דף ב ע"א" $\rightarrow$ דף 2 עמוד 1): **25 נקודות**.
  * התאמת פרק/סימן מדויקת: **20 נקודות**.
  * התאמת סעיף/פסוק מדויקת: **15 נקודות**.

#### 3. בונוס זיהוי ספר ומסכת ($S_{\text{book}}$): עד 20 נקודות
* זיהוי מפורש של שם ספר מתוך אינדקס אוצריא (כגון "מסכת ברכות", "שולחן ערוך"): **20 נקודות**.
* זיהוי ספר באמצעות הרחבת ראשי תיבות (כגון "או"ח" $\rightarrow$ "אורח חיים"): **18 נקודות**.

#### 4. בונוס רצף מילים וקרבה ($S_{\text{proximity}}$): עד 10 נקודות
* מילים המופיעות ברצף מדויק ללא מילים חוצצות מקבלות **10 נקודות**.
* מילים המופיעות במרחק של 1–2 מילים זו מזו: **5 נקודות**.

#### 5. בונוס הקשר סביבתי ($S_{\text{context}}$): עד 10 נקודות
* אם הציטוט מופיע בתוך מסמך שעוסק במסכת/ספר מסוים (Contextual Hint): **10 נקודות**.

#### 6. הפחתות וקנסות ($P_{\text{common\_words}}$, $P_{\text{length\_diff}}$)
* **קנס מילים שכיחות ($P_{\text{common\_words}}$)**: מחיקת נקודות (עד $15-$ נקודות) אם רצף הציטוט מבוסס בעיקר על מילות מפתח שכיחות מדי (לדוגמה "אמר רב" ללא שם מסכת).
* **קנס פער באורך המחרוזת ($P_{\text{length\_diff}}$)**: מחיקת נקודות אם חלון הסריקה ארוך או קצר משמעותית מתבנית הציטוט הצפויה.

## 9. מנגנון הקישור והשילוב עם מאגר אוצריא

לאחר דירוג המועמדים, המועמד בעל הציון הגבוה ביותר מומר לאובייקט קישור תקני של אוצריא (`CitationMatch`).

### 9.1 מבנה אובייקט הקישור (`CitationMatch`)
```typescript
interface CitationMatch {
  id: string;                 // מזהה ייחודי (UUID/Hash)
  originalText: string;       // הטקסט המקורי בתוך מסמך המשתמש
  startIndex: number;         // אינדקס תו התחלה במסמך
  endIndex: number;           // אינדקס תו סיום במסמך
  confidenceScore: number;    // ציון התאמה סופי (0-100)
  status: 'confirmed' | 'ambiguous' | 'unresolved' | 'rejected';
  
  // פרטי מראה המקום באוצריא
  bookName: string;           // שם הספר באוצריא (לדוגמה: "בבלי ברכות")
  sectionName?: string;       // פרק / חטיבה
  dafOrSiman?: string;        // דף / סימן (לדוגמה: "ב.", "קנח")
  seifOrParagraph?: string;   // סעיף / הלכה / פסוק
  
  // נתוני קישור ישיר לאוצריא (Otzaria Link Scheme)
  otzariaUrl: string;         // URI ייעודי, לדוגמה: otzaria://book/בבלי%20ברכות/page/2
  candidates: Candidate[];   // רשימת מועמדים חלופיים לבחירת המשתמש
}
```

### 9.2 ממשק הגשר לאוצריא (`otzariaBridge.ts`)
1. **עבודה במצב עצמאי (Mock Library Mode)**:
   * שימוש באינדקס ספרים מובנה (`otzariaLibraryMock.ts`) הכולל את מבנה הש"ס, התנ"ך, שולחן ערוך, רמב"ם ומפרשים מרכזיים.
2. **עבודה במצב תוסף חי (Otzaria Plugin SDK v1.x)**:
   * תקשורת באמצעות `postMessage` מול אפליקציית האם של אוצריא.
   * שליחת שאילתות חיפוש במידת הצורך לקבלת טקסט המקור המלא.
   * פתיחת ספר במקום המדויק באוצריא בעת לחיצה על הקישור.
